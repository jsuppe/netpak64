Verified 16 October 2026 / local development session

Is it actually communicating?

Yes. A fresh ares session fetched the catalog, downloaded a 256KiB demo artifact, verified its digest and displayed “Download verified — 100%.” This is a recorded verification snapshot, not a public uptime monitor.

  1. Setup ROMMIPS code reads and writes the management ABI.
  2. ares NetPak devicePI management registers publish configuration and update state.
  3. Host network workerActs as the simulated MCU; performs real HTTP outside the emulation thread.
  4. Local update serviceServes health, compatible catalog and content-addressed artifact bytes.

Measured, not a timer

  • Health, catalog and artifact requests returned HTTP 200.
  • Live mailbox observed at 131,072 / 262,144 bytes, then complete.
  • ROM state reached ready / 100%; version 0.2.0-demo.
  • Staged artifact rehashed to the expected SHA-256.
  • Gameplay relay also active, with one connected client; no active game room in this check.

Separate paths

Update HTTP is not tunneled through the gameplay UDP relay. The management prototype uses a host-worker mailbox, not the earlier Verilator RTL packet frontend. The current update service listens only on the development host’s loopback interface; this public page is not an update endpoint.

Both service processes are managed by user systemd units. The ares check was left running after verification; this static page does not promise continuous availability.

USB-free hardware goal

What this proves. What comes next.

The selected physical concept is top cartridge → active interposer → console cartridge slot. The setup ROM and device model let us exercise the configuration/update workflow before committing that behavior to hardware.

Working in the prototype

  • Automatic/manual IPv4 draft editing and explicit Apply.
  • Static address validation; emulator-file settings persistence.
  • Real HTTP catalog/download/size and digest verification/staging.
  • 29 menu + 41 model assertions passing with native sanitizers.
  • Full emulator navigation, message dialogs and a successful PI Apply.

Still to qualify or build

  • Bind the management contract to actual FPGA/MCU firmware and Ethernet.
  • RTL/MCU/SPI timing, synthesis closure, electrical and cartridge-bus testing.
  • Signed releases, trust policy and production update hosting.
  • Power-loss-safe installation, bootloader/recovery and rollback.
  • Real N64/PAL/controller/TV readability and performance qualification.

Physical console + SummerCart64 ↔ PC bridge ↔ emulator gameplay was an earlier reference path. This new goal removes the USB/PC bridge; the simulated setup workflow alone does not prove the untethered board works.
