An experimental network adapter for Nintendo 64

The game sees a network device, not netplay.

NetPak64 defines a memory-mapped NIC on the N64 PI bus, connects it to a lightweight UDP relay, and lets games own their netcode. The same register-level contract targets emulators today and physical hardware tomorrow.

The objective

Give N64 software a durable, hardware-shaped networking contract.

Most emulator netplay synchronizes controllers outside the game. NetPak64 instead exposes registers, packet buffers, interrupts, rooms, peers, and a shared clock. A homebrew title can choose snapshots, prediction, reliable events, or lockstep—and keep the same ROM-side code when the transport changes.

One protocol, five cooperating pieces.

01

Versioned device spec

A 64 KiB Domain 2 window with capabilities, command mailbox, packet buffers, IRQ state, and epoch handling.

02

Thin ares integration

The emulator owns deterministic device state while a network thread only touches lock-free queues and atomics.

03

Game-facing library

Non-blocking datagrams, dynamic sessions, peer discovery, shared time, unreliable ch0, and reliable-ordered ch1.

04

Self-hosted relay

A compact Rust/Tokio UDP service with join codes, presence, NAT re-pinning, rate limits, and Prometheus metrics.

05

MK64 research build

Online menus and a deterministic multiplayer engine prove that a full commercial-era game can use the device model.

06

Hardware path

The selected USB-free path is an active cartridge interposer. Digital simulation and the setup-ROM management workflow are in progress; physical electricals and target firmware remain unqualified.

    In-game online flow, 2–4 player lockstep races and battles, synchronization diagnostics, and native CPU driving for automated race participants.
